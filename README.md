# @rabby-wallet/gnosis-sdk

Read a Safe, build and hash its transactions, and encode the calldata that
executes them.

The SDK **never holds a provider, never signs, and never broadcasts**. It gives
you a hash to sign and an unsigned transaction to send; how you sign and how you
send are yours.

Runtime dependencies: `viem` and `@safe-global/types-kit`.

## Quick start

```ts
import { createSafeClient, createEthCall, getSafeVersion, normalizeSignature }
  from "@rabby-wallet/gnosis-sdk";

const ethCall = createEthCall("https://rpc.example.org");     // any eth_call fn
const version = await getSafeVersion(ethCall, safeAddress);

const safe = createSafeClient({
  chainId: 137,
  safeAddress,
  version,
  ethCall,                 // optional — omit it and only on-chain reads are unavailable
  backend: openapiService, // required for chains routed through the backend proxy
});

// 1. Build (reads the nonce; pass overrides to stay fully offline)
const txData = await safe.buildTransaction({ to, value, data });

// 2. Hash locally — no RPC
const safeTxHash = safe.hashTransaction(txData);
const typedData = safe.getTransactionTypedData(txData); // for eth_signTypedData_v4

// 3. Sign it yourself, however you like
const raw = await myKeyring.sign(owner, safeTxHash);

// 4. Hand the raw signature back for Safe's V-value normalization
const signature = await normalizeSignature({
  signature: raw,
  signer: owner,
  method: "personal_sign",  // "eth_sign" | "personal_sign" | "eth_signTypedData"
  hash: safeTxHash,         // required for the two prefix-probing methods
});

// 5. Propose / confirm through the transaction service
await safe.proposeTransaction({ txData, safeTxHash, sender: owner, signature });
await safe.confirmTransaction(safeTxHash, signature);

// 6. Execute — the SDK only produces calldata
const execTx = safe.encodeExecTransaction(txData, signatures);
// => { to, data, value }
await myWallet.sendTransaction(execTx);
```

## Chain access

The only thing the SDK asks of a chain is an `eth_call`:

```ts
type EthCall = (tx: { to: string; data: `0x${string}` }) => Promise<`0x${string}`>;
```

Multi-chain is just one of these per chain. Supply your own, or wrap a JSON-RPC
caller with `ethCallFromRpc`, or use the bundled `createEthCall(url)`.

`ethCall` is optional. Hashing, encoding, typed data and every transaction
service call work without it; on-chain reads reject with a message saying what
is missing.

## Transaction service

`createSafeTxService` makes the "backend proxy or direct HTTP" decision once:

- chain resolves to an **absolute** URL → talks HTTP to Safe directly
- chain resolves to a **relative** proxy path → routes through the `backend` you
  pass, falling back to HTTP per method for anything the backend does not
  implement

HTTP failures throw `SafeTxServiceError`, which exposes `error.response.data`
so the service's own validation message stays reachable.

## Layout

```
src/
  core/        pure — no IO, no config. hash, typed data, signatures, encoding
  rpc/         eth_call plumbing and Safe reads
  txService/   transaction service interface + http / backend implementations
  chains/      chain registry (generated by scripts/update-tx-service-networks.js)
  client.ts    SafeClient — composes the above
```

`core/` is where the money is: safeTxHash derivation, the V-value rules, and
signature packing. It is pure and covered by differential tests against
`@safe-global/protocol-kit` and `ethers`, which are kept as dev-only oracles.

## Migrating from 1.x

| 1.x | now |
| --- | --- |
| `new Safe(address, version, web3Provider, chainId)` | `createSafeClient({ chainId, safeAddress, version, ethCall, backend })` |
| `Safe.adapter` / `Safe.openapiService` (static) | `backend` / `fetch` per client |
| `Safe.getSafeVersion({ address, provider })` | `getSafeVersion(ethCall, address)` |
| `safe.getBasicSafeInfo()` | `safe.getBasicInfo()` |
| `safe.getTransactionHash(tx)` (an `eth_call`) | `safe.hashTransaction(txData)` (local) |
| `safe.getSafeMessageHash(hash)` (an `eth_call`) | `safe.hashMessage(message)` (local) |
| `safe.signTransaction(tx)` | sign `safe.hashTransaction(...)` yourself, then `normalizeSignature` |
| `safe.postTransaction(tx, hash)` | `safe.proposeTransaction({ txData, safeTxHash, sender, signature })` |
| `safe.executeTransaction(tx)` (broadcast) | `safe.encodeExecTransaction(txData, sigs)` → you send it |
| `safe.getBalance()` | gone — read it yourself |
| `EthSafeTransaction` / `EthSafeSignature` objects | plain `SafeTransactionData` / `SafeSignature` objects |

`GNOSIS_SUPPORT_CHAINS`, `SafeTransactionItem` and friends are still exported
from both the package root and `dist/api`.
